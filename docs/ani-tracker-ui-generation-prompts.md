# Ani-tracker 纯提示词 UI 生成规范

更新时间：2026-07-18

## 1. 文档用途

本文档用于通过纯提示词生成 Ani-tracker 的 UI 界面、交互原型或前端视觉稿，不依赖 Figma，不要求生成器读取现有源码。

交付范围：

- 桌面端：Windows、macOS，共 8 个核心页面。
- 移动端：远程管理客户端，一级导航与桌面端一致，共 8 个入口；页面内容按移动端重新编排。
- 次级页面：新番发现·番剧详情，以及追番资源、追番规则和下载详情。
- 关键流程：追番资源、追番规则、下载详情、删除确认、批量下载、远程配对和在线播放。
- 完整状态：默认、悬停、聚焦、选中、禁用、加载、空、错误、成功、离线和深色主题。

推荐使用方法：

1. 先复制“全局母提示词”。
2. 再追加一个“页面提示词”。
3. 最后追加“状态与视口后缀”，指定尺寸、主题和状态。
4. 一次只生成一个页面或一个弹层，避免生成器压缩、遗漏功能。

示例组合：

```text
[全局母提示词]
[桌面端：首页 / 今日追番提示词]
[视口：1440 x 900；主题：浅色；状态：默认且包含真实业务数据]
```

## 2. 全局母提示词

以下内容可以直接作为每次生成任务的开头：

```text
请设计 Ani-tracker 的真实可操作应用界面。Ani-tracker 是本地桌面追番与 BT 下载管理工具，不是视频网站、内容社区或营销网站。用户需要发现季度新番、管理追番、配置字幕组和资源规则、搜索发布资源、管理下载任务、查看提醒，并从已下载文件启动播放器。

只生成应用本身的工作界面，不要生成落地页、登录营销页、功能介绍页或大面积 Hero。界面语言使用简体中文，应用名称必须写作“Ani-tracker”。不要使用 Lorem ipsum、无意义占位文字、虚构图表或用于解释界面如何使用的教学文案。使用符合追番场景的真实示例数据和真实动漫海报/封面；图片必须清晰、可辨认、不过度裁切，不要用抽象渐变或纯气氛图片代替内容。

视觉方向为“番剧编辑部”：使用类似漫画分镜和编辑台的层级关系，通过粗细边界、留白、标题层级、时间轴和内容图片划分信息，不要把所有区域都做成相同权重的大卡片。整体是安静、专业、适合长时间重复操作的桌面工具，同时保留适量动画感。基础色使用墨黑、纸白或冷白；主要操作使用珊瑚红；信息与焦点使用青蓝；警告使用明黄；成功使用绿色；破坏性操作使用深红。不要使用青绿色单色主题，不要使用装饰性渐变、发光光球、玻璃拟态、过度阴影或大面积紫蓝色。

所有颜色必须按语义角色组织，使浅色、深色和未来主题包共用同一结构。页面只能消费 background、foreground、card、popover、muted、accent、primary、secondary、border、input、ring、info、success、warning、destructive、sidebar 等语义角色，不要让页面结构依赖固定颜色。浅色与深色主题必须保持相同的信息层级和状态含义。

组件视觉和交互以 shadcn/ui new-york 风格、Radix 行为模型和 Lucide 图标为边界。优先使用 Sidebar、Button、Icon Button、Badge、Card、DropdownMenu、Command、Sheet、Drawer、Popover、Tabs、Input、InputGroup、Select、Checkbox、Switch、ToggleGroup、Field、FieldGroup、FieldSet、Progress、Alert、Empty、Skeleton、Tooltip 和 Sonner Toast。删除确认使用标准 AlertDialog 视觉。不要手绘已有的通用组件，不要在卡片内继续嵌套卡片。

圆角限制在 8px 以内：输入框和按钮 6px，普通面板 6px，海报卡 8px。主要边界使用 1px 实线，阴影只区分浮层和悬浮卡片，页面分区本身不要做成漂浮卡片。字距始终为 0，不使用负字距，不随视口宽度连续缩放字号。页面标题约 24-28px，分区标题 18px，列表标题 14-16px，正文 14px，辅助信息 12-13px。使用 Inter、Segoe UI、Microsoft YaHei 和系统字体栈。

桌面主规格为 1440 x 900，边界规格为 1024 x 768。桌面使用左侧导航、系统标题栏和页面级操作区；1440px 显示完整侧栏，1024px 可收为图标侧栏并通过 Tooltip 显示名称。Windows 与 macOS 共用内容结构，只在窗口控制区体现平台差异。页面标题、筛选区、内容区和固定操作栏之间必须层级明确。

移动主规格为 390 x 844，定位是连接桌面端的远程管理客户端。使用固定顶部应用栏和左侧全高导航 Sheet，不使用底部导航。导航入口与桌面端完全一致：首页、我的追番、新番发现、资源搜索、下载队列、提醒中心、下载源、设置。下载源和设置在移动端使用单列、分组和二级页面重新编排；涉及本地路径、批量下载、媒体扫描或复杂规则的操作应显示清晰的能力边界，不得生成空白页。所有移动端触控目标至少 44 x 44px，并处理安全区。

按钮必须使用清晰命令名称；熟悉操作可使用 Lucide 图标按钮，并提供 Tooltip 或可访问名称。长标题最多显示两行，不能挤压状态和操作区；单行路径、哈希和文件名使用截断并保留查看完整内容的方式。动态内容不能造成按钮、进度条、计数器或列表行跳动。

异步操作开始后禁用重复提交，按钮保留稳定宽度并显示加载图标与进行中文字。普通成功和短暂失败使用 Sonner Toast；会影响后续处理的重要异步结果同时进入提醒中心。页面或分区加载失败使用内联 Alert，并提供重试。加载使用与最终结构一致的 Skeleton；空状态使用 Empty，说明原因并只给一个最合适的下一步。

删除、清空、取消绑定、恢复默认等破坏性操作必须二次确认。确认弹窗写清对象名称、影响范围和是否会删除文件；默认焦点放在取消按钮，不允许把破坏性按钮做成主要默认操作。表单校验贴近字段显示，保存失败保留全部输入，关闭存在未保存修改的 Sheet 或 Drawer 时先确认放弃修改。

最终画面必须像一个已经接入真实数据的产品：无文字遮挡、无横向溢出、无未处理 placeholder、无重复按钮、无无效卡片、无桌面与移动能力混用。正文对比度至少 4.5:1，关键边界和焦点至少 3:1。
```

## 3. 推荐语义令牌

以下色值是生成提示词时的推荐默认值，不是不可替换的品牌常量。主题包可以替换数值，但不能改变语义角色。

| 角色 | 浅色建议 | 深色建议 | 用途 |
| --- | --- | --- | --- |
| `background` | `#F6F7F8` | `#101214` | 应用底色 |
| `foreground` | `#17191C` | `#F4F6F7` | 主文字 |
| `card/popover` | `#FFFFFF` | `#191C20` | 卡片与浮层 |
| `muted` | `#ECEFF2` | `#252A30` | 次级表面 |
| `muted-foreground` | `#69717C` | `#AAB1BA` | 辅助文字 |
| `border/input` | `#D7DCE2` | `#343A42` | 边界与输入框 |
| `primary` | `#E65B50` | `#FF756B` | 主要操作、当前重点 |
| `info/accent` | `#2D8FA5` | `#58BDD0` | 信息、链接、焦点 |
| `warning` | `#E5B936` | `#F2CF57` | 待确认、异常提醒 |
| `success` | `#2F8A68` | `#55B68A` | 完成、在线、已绑定 |
| `destructive` | `#C83F4B` | `#FF6B75` | 删除、失败、不可恢复操作 |

补充规则：

- 珊瑚红只用于主要命令和少量选中强调，不能染满背景。
- 青蓝用于链接、焦点环、信息 Badge 和进度，不与珊瑚红争夺主按钮权重。
- 明黄背景必须搭配深色文字，不使用浅黄文字。
- 深色模式中海报和内容图保持真实亮度，不添加统一深色蒙层。
- 状态不能只依赖颜色，必须同时显示图标或文字。

## 4. 全局布局与操作规则

### 4.1 桌面应用壳

- 顶部保留 36-40px 平台标题栏。macOS 左侧显示红黄绿窗口按钮，Windows 右侧显示最小化、最大化和关闭。
- 1440px 使用约 220-232px 完整侧栏；1024px 使用约 68-76px 图标侧栏。
- 侧栏顶部显示 Ani-tracker 名称和简洁播放标志，中部显示 8 个页面入口，底部显示下载核心状态和未读提醒入口。
- 侧栏入口顺序固定：首页、我的追番、新番发现、资源搜索、下载队列、提醒中心、下载源、设置。
- 当前页面使用实底选中条、图标和文字共同标识；图标侧栏悬停时显示 Tooltip。
- 页面内容区使用 24px 左右边距，页面标题区不放进卡片。页面主标题左对齐，关键命令位于右上方。
- 页面内滚动时侧栏和标题栏保持固定；只有当前页面内容滚动。

### 4.2 移动应用壳

- 顶部应用栏高约 52-56px，显示菜单按钮、当前页标题、桌面端连接状态和必要的单个页面操作。
- 移动主导航不使用底部栏，点击菜单按钮后从左侧打开全高 `Sheet`，完整显示与桌面端相同的 8 个入口。
- 列表和内容使用单列布局，左右边距 16px，区块间距 16-20px。
- 筛选过多时使用 Popover、底部 Drawer 或独立二级筛选页，不让顶部应用栏塞满控件。
- 二级详情使用全屏 Drawer 或新页面，顶部提供返回按钮；不能使用只有桌面鼠标才能发现的悬停操作。

### 4.3 组件选择

| 场景 | 组件规则 |
| --- | --- |
| 明确命令 | `Button`；主要动作一个页面同时最多一个实心主按钮 |
| 图标操作 | `Button` 的图标尺寸，配 `Tooltip` 和可访问名称 |
| 2-5 个互斥选项 | `ToggleGroup`，例如分辨率和明暗模式 |
| 二元设置 | `Switch`，标签点击也应切换 |
| 多选 | `Checkbox` 或多选 `ToggleGroup` |
| 长表单 | `FieldGroup`、`FieldSet` 和分区 Tabs，不用无尽单列 |
| 页面切换 | 桌面使用 `Sidebar`，移动使用顶部应用栏 + `Sheet` 导航，不用 Tabs 冒充主导航 |
| 同一页面视图 | `Tabs`，例如 RSS 订阅/资源搜索 |
| 桌面侧面板 | `Sheet`，必须有标题、关闭按钮和固定操作栏 |
| 移动二级面板 | 全屏 `Drawer`，顶部返回、正文独立滚动 |
| 卡片更多操作 | 桌面 `DropdownMenu`；移动底部动作菜单 |
| 快速筛选 | `Select`、`Popover` 或 `Command` |
| 状态标签 | `Badge`，文字不能只写颜色含义 |
| 加载 | 与最终布局一致的 `Skeleton` |
| 空状态 | `Empty`，包含原因和一个下一步 |
| 分区错误 | `Alert`，保留已有可用数据 |
| 短暂反馈 | `Sonner Toast` |
| 删除确认 | 标准 `AlertDialog` 视觉；该组件当前属于建议组件，不在本任务中安装 |

### 4.4 通用操作闭环

| 操作 | 进行中 | 成功 | 失败 |
| --- | --- | --- | --- |
| 保存设置/规则 | 禁用保存和重复关闭，显示“保存中” | 关闭或保留面板并 Toast“已保存” | 保留输入，字段错误就近显示，顶部 Alert 汇总 |
| 刷新列表 | 保留旧数据，刷新按钮旋转，显示最后刷新时间 | 无打扰更新计数，可用轻量 Toast | 保留旧数据，在对应区块显示 Alert 和重试 |
| 添加追番 | 当前卡片按钮显示“添加中” | 按钮变为“已在我的追番”，Toast 成功 | 恢复按钮，Toast 或内联 Alert |
| 添加下载 | 当前行按钮显示“添加中” | 行状态变为“已加入”，Toast 成功并可去下载队列 | 行保留，展示来源返回的可读错误 |
| 批量下载 | 固定底栏显示选中数并锁定重复提交 | Toast 显示成功数/失败数，失败项保留选中 | 不清空选择，提供失败项和重试 |
| 复制地址/代码 | 图标按钮按下反馈 | Toast“已复制” | Toast“复制失败”并允许手动选择 |
| 删除/清空/解绑 | 打开确认弹窗 | 关闭弹窗，更新列表，Toast 成功 | 关闭加载态但保留对象，Toast 错误 |

### 4.5 搜索与筛选

- 输入关键词时可以显示追番联想；按 Enter 执行搜索，Esc 关闭联想。
- 选择联想项后显示“已关联：番剧名”和解析出的集数 Badge。
- 筛选只改变当前视图，不显示成功 Toast。
- 清空关键词时立即恢复未筛选数据。
- 搜索结果必须显示本次关键词、已搜索来源数量、结果数量和异常来源数量。
- 不因单个下载源失败清空其他来源的成功结果。

### 4.6 Sheet、Drawer 与菜单

- 桌面资源 Sheet 建议宽 800px，可在 760-840px 内调整；规则 Sheet 建议宽 760-800px。
- Sheet 的标题区和底部操作区固定，只有正文滚动。
- 打开 Sheet 后保留背景页面位置，背景使用中性遮罩，不模糊海报。
- Esc、右上角关闭按钮和点击遮罩可以关闭无修改面板；存在未保存内容时必须先确认。
- 桌面 DropdownMenu 点击或键盘打开；不把核心操作设置为仅悬停才能使用。
- 菜单破坏项放在末尾，使用分隔线和破坏性文字。

### 4.7 下载状态与可用操作

| 状态 | 显示 | 主要可用操作 |
| --- | --- | --- |
| 排队中 | 中性 Badge、0% 或等待位置 | 暂停、移除 |
| 获取元数据 | 青蓝 Badge、不确定进度 | 暂停、移除 |
| 下载中 | 青蓝 Badge、进度、速度、ETA | 暂停、查看文件、移除 |
| 等待连接 | 明黄 Badge、保留已有进度 | 继续/重新连接、暂停、移除 |
| 已暂停 | 明黄 Badge、保留进度 | 继续、移除 |
| 校验中 | 信息 Badge、校验进度 | 等待、移除按钮禁用或谨慎提示 |
| 移动文件 | 信息 Badge、稳定进度 | 等待，不允许重复扫描 |
| 已完成 | 绿色 Badge、100% | 播放、定位文件、扫描媒体、移除任务 |
| 做种中 | 绿色或青蓝 Badge、100%、上传速度 | 暂停做种、播放、定位文件 |
| 错误 | 红色 Badge、错误摘要 | 重试/继续、查看原因、移除 |
| 文件缺失 | 红色 Badge、路径提示 | 重新检查、定位目录、移除 |

文件选择规则：

- 文件复选框只改变下载优先级，不直接删除文件。
- 未选文件降低文字强调并加删除线，但仍可重新选中。
- 文件名优先显示，右侧固定显示大小和单文件进度。
- 修改失败时恢复原选择并显示错误 Toast。

### 4.8 通知规则

- 保存成功、复制成功、开始刷新、加入下载等短时反馈使用 Toast，不占据页面固定空间。
- 自动扫描结果、下载完成、下载失败、默认字幕组缺失和远程服务异常写入提醒中心。
- 重复提醒按对象和时间合并，列表中显示次数，不连续堆叠完全相同的行。
- 未读通过圆点、字重和“未读”文字共同表示。
- 桌面系统通知只作为外部提醒，不替代应用内提醒记录。

## 5. 桌面端页面提示词

以下每段均可单独复制；如需获得最稳定的风格一致性，仍建议在前面附加“全局母提示词”。

### 5.1 首页 / 今日追番

页面目标：用户打开应用后立即知道“今天更新什么、哪里需要处理、正在下载什么”，不要让统计数字压过任务本身。

```text
请生成 Ani-tracker 桌面端“首页 / 今日追番”实际应用界面，视口 1440 x 900。使用番剧编辑部视觉、冷白工作台背景、墨黑文字、珊瑚红主要操作、青蓝信息、明黄提醒、绿色完成状态，圆角不超过 8px。左侧显示 8 项完整导航，当前选中“首页”。不要使用营销页 Hero，不要把页面做成一排同权重的大统计卡。

页面顶部是非卡片式标题区：标题“今日追番”，副标题显示“2026 年 7 月 18 日 · 周六”，右侧放珊瑚红主按钮“扫描更新”和次要文字“上次扫描 12:58”。扫描按钮点击后显示旋转图标和“扫描中”，保留页面旧数据；完成后用 Toast 汇报找到的资源数，重要结果进入提醒中心。

标题下方放一条紧凑摘要带，显示“在追 12”“今日更新 3”“下载中 2”“未读提醒 4”，数字用于扫读，不做四张大卡。

首屏主体使用约 2:1 双栏。左侧主区域标题“今日更新”，使用清晰时间轴或编辑清单，每行包含 48-64px 海报缩略图、番剧中文名、原语言副标题、第几集、计划播出时间、字幕组和状态 Badge。示例包括“地狱模式 第二季 · 第 3 集 · 20:00 · 已匹配 · LoliHouse”和“无职转生 第三季 · 第 4 集 · 23:00 · 已开播”。行尾根据状态显示一个明确操作：未匹配显示“查找资源”，下载中显示“查看任务”，已下载显示播放图标。标题最多两行，行高固定。
```

```text
概览分区位于首屏之后，使用 12 列或双栏布局。

左侧为“剧情简介”：显示完整简介，超过约 6 行时默认截断，提供“展开全部”和“收起”。展开后允许自然撑高并继续滚动，文本使用 14-15px、约 1.6 行高，不使用大段粗体或装饰性引号。

右侧为“核心信息”，使用紧凑字段表或两列信息网格，不使用大统计卡：首播年份、首播月份、首播日期、播出季度、播出状态、预计集数、当前目录集数、评分、评分人数、评分来源、数据来源、最后同步时间。字段标签使用 12px muted-foreground，字段值使用 14px 墨黑。未知值统一显示“未知”或“未提供”，不存在的字段不留空白行。

## 播出信息分区

显示首播日期、首播星期、预计播出时间、播出时区（如有）、当前播出状态、预计集数、已播集数、下集预计日期、当前季度和月份。

播出状态包括：未开播、连载中、已完结、播出延期、状态未知。正在播出使用青蓝或绿色 Badge，延期和未确认使用明黄色 Badge，状态不能只依赖颜色。

如果数据源提供，显示题材标签、制作公司、动画制作公司、播出平台、发行地区、监督、系列构成、角色设计、音乐制作、原作类型和原作作者。

## 别名与来源分区

“搜索别名”显示中文别名、日文标题、英文标题、罗马音和自定义别名。每行显示语言 Badge、别名文本和复制按钮；长别名最多两行，点击后可以查看完整文本。

## 固定操作与移动端编排

桌面端向下滚动后，可以在顶部显示 56-64px 的吸顶操作条：左侧为缩略海报和单行中文标题，中间为追番状态和首播月份，右侧为“添加追番”和“搜索资源”。不要同时出现两个相同的“添加追番”按钮。

移动端首屏顺序为：返回按钮和页面标题、海报缩略图、中文标题和原语言标题、首播/评分/季度/状态、添加追番/搜索资源、简介摘要、核心信息。海报约 112-128px 宽，不能占据整个首屏。

移动端后续顺序为：完整简介、播出信息、制作与标签、别名、外部来源、相关资源。低权重信息使用折叠分区或二级详情页。移动端不使用固定底部全局导航；如果需要保留主要动作，只在顶部应用栏或页面顶部操作区显示。

## 数据缺失与异常状态

加载状态保留返回按钮和页面骨架，海报、标题、Badge、简介和字段表使用同结构 Skeleton，加载完成后不能跳动。

封面缺失时显示固定比例 ImageOff 占位和“暂无封面”。部分字段缺失时隐藏不存在的字段，关键未知值显示“未知”，不得凭空补齐演员、集数、评分或制作公司。

数据源异常时保留缓存和已加载资料，在“来源与同步信息”区域显示 Alert 和“重试同步”。整页加载失败时保留导航和返回入口，显示“番剧详情加载失败”、非技术化原因和“重试”，不显示堆栈或白屏。

已在我的追番时显示绿色“已在我的追番”，主按钮变为禁用或次要按钮，显示“编辑追番规则”，仍允许搜索资源和查看外部来源。
```

### 8.3 离线、鉴权失效与重连

- 短时离线：保留缓存，顶部显示“正在重连”，禁用写操作。

- [ ] 长标题、文件名、路径和 Badge 不遮挡按钮或下一行。
- [ ] 进度、计数、按钮和图标拥有稳定尺寸，动态数据不会导致跳动。

### 10.2 操作闭环

- [ ] 每个按钮都有明确触发结果。
- [ ] 每个异步操作都有进行中、成功和失败反馈。
- [ ] 筛选不会错误弹 Toast，保存和添加成功使用 Toast。
- [ ] 重要异步结果会进入提醒中心。
- [ ] 删除、清空、解绑和恢复默认都有明确确认。
- [ ] 保存失败保留输入，关闭未保存表单会确认。
- [ ] 部分来源失败不会清空其他成功数据。
- [ ] 批量下载显示总数、已选数、成功数和失败数。

### 10.3 平台边界

- [ ] 桌面端包含 8 个核心页面。
- [ ] 移动端没有底部导航，使用顶部应用栏和左侧全高导航 Sheet。
- [ ] 移动端与 PC 端均包含相同的 8 个一级入口，顺序、图标和选中状态一致。
- [ ] 移动端下载源和设置具有适配页面；受限本地操作显示只读状态，不出现死入口。
- [ ] 移动端没有删除任务、媒体扫描、规则编辑或字幕组修改。
- [ ] 移动端详情使用全屏 Drawer，并保留返回路径。
- [ ] Windows 与 macOS 只在窗口控制区不同。

### 10.4 可访问性与状态

- [ ] 正文对比度至少 4.5:1，焦点与关键边界至少 3:1。
- [ ] 状态同时使用文字/图标和颜色。
- [ ] 移动触控目标至少 44 x 44px。
- [ ] 图标按钮具备 Tooltip 或可访问名称。
- [ ] 加载、空、错误、禁用、聚焦、选中和深色状态齐全。
