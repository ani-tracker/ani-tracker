# Ani-tracker Stitch UI 全量改版实施计划

更新时间：2026-07-19

## 1. 目标

- 将 Stitch 项目中的有效设计完整落地到 Electron、桌面边界视口和远程 PWA。
- 统一导航、页面标题、信息密度、浮层、状态反馈和响应式行为。
- 保留现有业务能力、暗黑模式、自定义调色、主题导入导出和远程权限边界。
- 页面只消费语义令牌，不在业务组件中写死主题颜色。

## 6. shadcn/ui 实施约束

- 先复用已安装组件，再搜索官方 `@shadcn` 注册表；新增组件前执行 `docs`、`--dry-run` 和 `--diff`。
- 不使用 `--overwrite`；不覆盖已本地修改的基础组件。
- 表单使用 `FieldGroup`、`Field`、`FieldSet`；2-5 个互斥选项使用 `ToggleGroup`。
- 通知使用 Sonner Toast；重要异步结果继续进入提醒中心。
- 加载、空、错误分别使用 `Skeleton`、`Empty`、`Alert`。
- `Sheet`、`Drawer`、`Dialog` 必须有可访问标题；图标按钮必须有 Tooltip 或可访问名称。
- 页面颜色只使用语义令牌；不在页面写 `dark:` 固定色或原始色值。

## 9. 量化验收指标

- 视口：`1440x900`、`1024x768`、`768x1024`、`390x844`。
- 主题：浅色、深色、跟随系统、至少 1 个导入的自定义主题。
- 对比度：正文至少 `4.5:1`；焦点和关键边界至少 `3:1`。
- 触控目标：移动端至少 `44x44px`。
- 页面状态：默认、加载、空、局部错误、整页错误、禁用、进行中、离线。
- 布局：无非预期横向溢出、文字遮挡、按钮跳动、空白 Badge 或浮层越界。
- 功能：追番 CRUD、资源搜索、批量下载、任务控制、来源配置、设置保存和主题导入不得回归。
- 工程检查：`pnpm.cmd run typecheck`、`pnpm.cmd run test:parsers`、`pnpm.cmd build`、`git diff --check`。

## 10. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| Stitch 页面局部导航尺寸不一致 | 只采用 D1 的全局导航规范，忽略页面稿内 232/256px 的局部值 |
| 截图未覆盖长页面底部 | 使用完整 HTML、现有字段和滚动容器逐项核对 |
| `MyAnimePage`、`SettingsPage` 体积过大 | 先按业务边界拆分，再迁移视觉；不改变共享契约 |
| 固定颜色破坏暗黑或用户主题 | 对 renderer 执行固定色扫描，逐项改为语义令牌 |
| 远程端误暴露桌面能力 | 保留 `isElectronClient` 和页面白名单，独立执行权限回归 |
| 主题文件破坏布局或可读性 | 仅接受声明式 v1 白名单；限制文件大小、圆角范围和颜色格式 |

## 11. 本轮不包含

- 不在应用内接入图片识别模型或外部 AI 服务。
- 不修改主题 schema 版本，不接受任意 CSS、JavaScript 或未知令牌。
- 不修改主进程业务契约、下载引擎和持久化结构，除非 UI 实施发现真实缺口并另行审核。

图片取色通过 [image-to-ani-theme-prompt.md](./image-to-ani-theme-prompt.md) 在外部视觉模型中完成，输出文件直接使用设置页现有导入流程。
